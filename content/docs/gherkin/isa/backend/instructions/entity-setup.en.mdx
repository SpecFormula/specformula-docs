EntitySetup lets you declare test precondition data directly in Gherkin, without writing INSERT statements in Step Definitions.

## Mapping to Entity Mapping

The EntitySetup instruction maps business entity names to actual database tables through **entity_to_table_mapping.yml**.

### Mapping Mechanism

```yaml
# entity_to_table_mapping.yml
entity_to_table_mapping:
  - user: users
  - todo: todos
  - order: orders
  - product: products
```

```gherkin
# Gherkin uses business language
Given prepare a user, with table:
  | name  | email             |
  | Alice | alice@example.com |

# SpecFormula automatically maps to users table
# INSERT INTO users (name, email) VALUES ('Alice', 'alice@example.com')
```

### Mapping Table

| Gherkin Element | Mapping Source |
|-----------------|----------------|
| `user` | `entity_to_table_mapping` key |
| `users` table | `entity_to_table_mapping` value |
| `name`, `email` fields | Database table Schema definition |

### Naming Conventions

**Entity names**: Use Chinese or English names familiar to the business team

```yaml
# ✅ Recommended: business language
entity_to_table_mapping:
  - member: members
  - order: orders
  - product: products

# ❌ Avoid: technical names
entity_to_table_mapping:
  - member_entity: members
  - tbl_order: orders
```

**Field name conversion**: DataTable uses camelCase, automatically mapped to database snake_case

```
Gherkin: userId      → DB: user_id
Gherkin: orderDate   → DB: order_date
Gherkin: createdAt   → DB: created_at
Gherkin: isActive    → DB: is_active
```

### Schema Validation

SpecFormula reads database Schema to validate that fields in DataTable exist:

```sql
-- src/test/resources/specs/data/schema.sql
CREATE TABLE users (
    user_id BIGINT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(255) NOT NULL UNIQUE,
    status VARCHAR(20) DEFAULT 'ACTIVE',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

```gherkin
# ✅ Correct: fields exist in Schema
Given prepare a user, with table:
  | name  | email             | status |
  | Alice | alice@example.com | ACTIVE |

# ❌ Lint error: field does not exist
Given prepare a user, with table:
  | name  | emailAddress      |    # emailAddress doesn't exist, should be email
  | Alice | alice@example.com |
```

## Basic Usage

```gherkin
Given prepare a user, with table:
  | >Alice.id | name  | email             | status |
  | <userId   | Alice | alice@example.com | ACTIVE |
```

This syntax will:
1. Insert a record into the `users` table
2. Query back the auto-generated `userId` from the database
3. Store `userId` in variable `Alice.id`

## Why Not Use API to Create Precondition Data?

Creating precondition data through API causes test coupling—if the "create user" API has a bug, all tests depending on that user will fail, even if the feature being tested is completely correct.

```gherkin
# ❌ Using API: create user API bug affects all tests
When (No Actor) create user, call table:
  | name  | email             |
  | Alice | alice@example.com |

# ✅ EntitySetup: direct database insert, unaffected by API
Given prepare a user, with table:
  | name  | email             |
  | Alice | alice@example.com |
```

## Field Name Conversion

DataTable uses camelCase, the framework automatically maps to database snake_case:

```
DataTable: orderDate  → DB: order_date
DataTable: userId     → DB: user_id
DataTable: createdAt  → DB: created_at
```

## Type Conversion

Values in DataTable are all strings, the framework auto-converts based on database column definitions:

| Input | Conversion Result |
|-------|-------------------|
| `"123"` | Integer / Long / BigDecimal |
| `"2026-01-27"` | LocalDate |
| `"2026-01-27T10:00:00"` | LocalDateTime |
| `@time(now)` | Current Mock time |
| `@date(now-1d)` | Yesterday's date |

## Variable Extraction

Use `>` and `<` pairs to extract auto-generated values from the database (e.g., auto-increment ID):

```gherkin
Given prepare an order, with table:
  | >order1.id | >order1.number | customerId | amount |
  | <orderId   | <orderNumber   | $Alice.id  | 1000   |
```

After execution:
- `order1.id` = `orderId` generated by database
- `order1.number` = `orderNumber` generated by database

## Variable Reference

Use `$variable` to reference previously stored variables:

```gherkin
Given prepare a user, with table:
  | >Alice.id | name  |
  | <userId   | Alice |

Given prepare a todo, with table:
  | userId    | title    |
  | $Alice.id | Buy milk |
```

## Error Handling

### Lint Phase

| Error | Description |
|-------|-------------|
| Entity not defined | Entity not found in `entity_to_table_mapping` |
| Field not found | Field in DataTable not found in table definition |

### Runtime

| Error | Description |
|-------|-------------|
| INSERT failed | Database constraint violation (unique key conflict, NOT NULL, etc.) |

## Complete Example

```gherkin
Feature: Create Todo

  Background:
    Given current time is "2026-01-27T10:00:00"
    Given prepare a user, with table:
      | >Alice.id | name  | email             | passwordHash | status |
      | <userId   | Alice | alice@example.com | password123  | ACTIVE |

  Example: Create a todo item
    When (UID="$Alice.id") create todo, call table:
      | >todo1.id | title    |
      | <todoId   | Buy milk |
    Then create todo(201) response, with table:
      | todoId    | userId    | title    |
      | $todo1.id | $Alice.id | Buy milk |
```
