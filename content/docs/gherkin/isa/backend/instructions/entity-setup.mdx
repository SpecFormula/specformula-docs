EntitySetup 讓你直接在 Gherkin 中宣告測試的前置資料，無需在 Step Definition 中撰寫 INSERT 語句。

## 與 Entity Mapping 的對應關係

EntitySetup 指令透過 **entity_to_table_mapping.yml** 將業務實體名稱對應到實際的資料表。

### 對應機制

```yaml
# entity_to_table_mapping.yml
entity_to_table_mapping:
  - 使用者: users
  - 待辦事項: todos
  - 訂單: orders
  - 商品: products
```

```gherkin
# Gherkin 使用業務語言
Given 準備一個使用者, with table:
  | name  | email             |
  | Alice | alice@example.com |

# SpecFormula 自動對應到 users 資料表
# INSERT INTO users (name, email) VALUES ('Alice', 'alice@example.com')
```

### 對應表

| Gherkin 元素 | 對應來源 |
|-------------|----------|
| `使用者` | `entity_to_table_mapping` 的 key |
| `users` 資料表 | `entity_to_table_mapping` 的 value |
| `name`, `email` 欄位 | 資料表 Schema 定義 |

### 命名規則

**Entity 名稱**：使用業務團隊熟悉的中文或英文名稱

```yaml
# ✅ 推薦：業務語言
entity_to_table_mapping:
  - 會員: members
  - 訂單: orders
  - 商品: products

# ❌ 避免：技術名稱
entity_to_table_mapping:
  - member_entity: members
  - tbl_order: orders
```

**欄位名稱轉換**：DataTable 使用 camelCase，自動對應資料庫的 snake_case

```
Gherkin: userId      → DB: user_id
Gherkin: orderDate   → DB: order_date
Gherkin: createdAt   → DB: created_at
Gherkin: isActive    → DB: is_active
```

### Schema 驗證

SpecFormula 會讀取資料庫 Schema 來驗證 DataTable 中的欄位是否存在：

```sql
-- src/test/resources/specs/data/schema.sql
CREATE TABLE users (
    user_id BIGINT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(255) NOT NULL UNIQUE,
    status VARCHAR(20) DEFAULT 'ACTIVE',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

```gherkin
# ✅ 正確：欄位存在於 Schema
Given 準備一個使用者, with table:
  | name  | email             | status |
  | Alice | alice@example.com | ACTIVE |

# ❌ Lint 錯誤：欄位不存在
Given 準備一個使用者, with table:
  | name  | emailAddress      |    # emailAddress 不存在，應為 email
  | Alice | alice@example.com |
```

## 基本用法

```gherkin
Given 準備一個使用者, with table:
  | >Alice.id | name  | email             | status |
  | <userId   | Alice | alice@example.com | ACTIVE |
```

這段語法會：
1. 在 `users` 資料表插入一筆記錄
2. 從資料庫反查自動產生的 `userId`
3. 將 `userId` 存入變數 `Alice.id`

## 為什麼不用 API 建立前置資料？

透過 API 建立前置資料會造成測試耦合——如果「建立使用者」API 有 bug，所有依賴該使用者的測試都會連帶失敗，即使被測功能完全正確。

```gherkin
# ❌ 用 API 建立：建立使用者 API 有 bug 會影響所有測試
When (No Actor) 建立使用者, call table:
  | name  | email             |
  | Alice | alice@example.com |

# ✅ EntitySetup：直接插入資料庫，不受 API 影響
Given 準備一個使用者, with table:
  | name  | email             |
  | Alice | alice@example.com |
```

## 欄位名稱轉換

DataTable 使用 camelCase，框架自動對應資料庫的 snake_case：

```
DataTable: orderDate  → DB: order_date
DataTable: userId     → DB: user_id
DataTable: createdAt  → DB: created_at
```

## 型別轉換

DataTable 中的值皆為字串，框架根據資料庫欄位定義自動轉型：

| 輸入 | 轉換結果 |
|------|----------|
| `"123"` | Integer / Long / BigDecimal |
| `"2026-01-27"` | LocalDate |
| `"2026-01-27T10:00:00"` | LocalDateTime |
| `@time(now)` | 當前 Mock 時間 |
| `@date(now-1d)` | 昨天日期 |

## 變數擷取

使用 `>` 和 `<` 配對擷取資料庫自動產生的值（如 auto-increment ID）：

```gherkin
Given 準備一個訂單, with table:
  | >order1.id | >order1.number | customerId | amount |
  | <orderId   | <orderNumber   | $Alice.id  | 1000   |
```

執行後：
- `order1.id` = 資料庫產生的 `orderId`
- `order1.number` = 資料庫產生的 `orderNumber`

## 引用變數

使用 `$variable` 引用先前儲存的變數：

```gherkin
Given 準備一個使用者, with table:
  | >Alice.id | name  |
  | <userId   | Alice |

Given 準備一個待辦事項, with table:
  | userId    | title  |
  | $Alice.id | 買牛奶 |
```

## 錯誤處理

### Lint 階段

| 錯誤 | 說明 |
|------|------|
| Entity 未定義 | `entity_to_table_mapping` 中找不到對應的 entity |
| 欄位不存在 | DataTable 中的欄位在資料表定義中找不到 |

### 執行階段

| 錯誤 | 說明 |
|------|------|
| INSERT 失敗 | 資料庫約束違反（唯一鍵衝突、NOT NULL 等） |

## 完整範例

```gherkin
Feature: 新增待辦事項

  Background:
    Given 現在時間為 "2026-01-27T10:00:00"
    Given 準備一個使用者, with table:
      | >Alice.id | name  | email             | passwordHash | status |
      | <userId   | Alice | alice@example.com | password123  | ACTIVE |

  Example: 新增一筆待辦事項
    When (UID="$Alice.id") 新增待辦事項, call table:
      | >todo1.id | title  |
      | <todoId   | 買牛奶 |
    Then 新增待辦事項(201)回應, with table:
      | todoId    | userId    | title  |
      | $todo1.id | $Alice.id | 買牛奶 |
```
