---
title: EntityNonExistenceValidate
description: 驗證資料庫記錄的不存在性
---

EntityNonExistenceValidate 讓你驗證記錄已從資料庫中刪除，常用於測試刪除操作。

## 基本用法

```gherkin
And 應該不存在一個待辦事項, with table:
  | todoId    | userId    |
  | $todo1.id | $Alice.id |
```

這段語法會：
1. 以提供的欄位作為查詢條件
2. 驗證查詢結果為空（記錄不存在）

## 使用場景

刪除操作後，確認記錄已從資料庫移除：

```gherkin
When (UID="$Alice.id") 刪除待辦事項, call table:
  | P:todoId  |
  | $todo1.id |
Then 刪除待辦事項(200)回應, with table:
  | message  |
  | 刪除成功 |
And 應該不存在一個待辦事項, with table:
  | todoId    |
  | $todo1.id |
```

## 查找策略

### PK 查詢（優先）

提供完整主鍵：

```gherkin
| todoId    |
| $todo1.id |
```

### Probe 查詢

使用非 PK 欄位作為查詢條件：

```gherkin
| userId    | title  |
| $Alice.id | 買牛奶 |
```

## 欄位名稱轉換

DataTable 使用 camelCase，框架自動對應資料庫的 snake_case：

```
DataTable: orderId   → DB: order_id
DataTable: productId → DB: product_id
```

## 限制

此指令不支援：
- CAS 約束符號（`&...`）
- VAR 擷取鍵（`>contextKey`）
- 回應來源欄位（`<executionKey`）

## 錯誤處理

### Lint 階段

| 錯誤 | 說明 |
|------|------|
| Entity 未定義 | `entity_to_table_mapping` 中找不到 |
| 欄位不存在 | 欄位在資料表定義中找不到 |
| 不支援的符號 | 使用了 CAS 或 VAR 擷取語法 |

### 執行階段

| 錯誤 | 說明 |
|------|------|
| 記錄仍然存在 | 預期不存在的記錄實際存在 |
| 缺少查詢條件 | 未提供任何欄位作為查詢條件 |

## 完整範例

```gherkin
Feature: 刪除待辦事項

  Background:
    Given 準備一個使用者, with table:
      | >Alice.id | name  | email             | status |
      | <userId   | Alice | alice@example.com | ACTIVE |

  Example: 刪除一筆待辦事項
    When (UID="$Alice.id") 新增待辦事項, call table:
      | >todo1.id | title  |
      | <todoId   | 買牛奶 |
    When (UID="$Alice.id") 刪除待辦事項, call table:
      | P:todoId  |
      | $todo1.id |
    Then 刪除待辦事項(200)回應, with table:
      | message  |
      | 刪除成功 |
    And 應該不存在一個待辦事項, with table:
      | todoId    | userId    |
      | $todo1.id | $Alice.id |
```
